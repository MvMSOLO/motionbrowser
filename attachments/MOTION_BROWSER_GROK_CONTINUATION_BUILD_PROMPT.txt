2. PRODUCT CONTEXT — WHAT MOTION BROWSER IS SUPPOSED TO BE
============================================================

MOTION BROWSER is a mobile-first spatial browser concept. The user opens the app and sees a premium, immersive 3D digital environment. The environment is already loaded locally so the user does not wait for the scene after every action.

A minimal address/search field appears in the 3D environment. The user can type a website name or URL, for example:
- Instagram
- Instagram.com
- YouTube
- YouTube.com
- another normal website/domain

The intended experience is to show the REAL website — not an imitation, screenshot, mock feed, or clone — inside a floating browser panel that appears to belong to the 3D environment. Real page content, navigation, and login must remain the real website's own content and functionality wherever the platform permits it.

The central differentiator is optional physical phone-motion control. The intended primary mapping is:
- gently tilt phone upward: next feed item / next Reel, when the active destination supports it;
- tilt downward: previous feed item, when supported;
- tilt left: open the comments/context panel, when supported;
- tilt right: close the comments/context panel / return;
- while comments are open, tilt up/down: scroll comments;
- return to neutral between distinct gestures.

The user must always retain normal touch controls. Motion control is optional, can be disabled instantly, and must not trigger while the user is typing, using an overlay, or when the app is backgrounded.

The intended final product is a NATIVE ANDROID APP using Android WebView and device sensors, with a 3D scene surrounding the real website surface. The product itself must NOT depend on AI APIs, cloud AI, API keys, paid AI models, or runtime AI calls. No AI feature is part of the shipped product.

Important browser security limitations:
- A normal web app cannot freely embed every website. X-Frame-Options and Content-Security-Policy frame-ancestors can block an iframe. Instagram, YouTube, TikTok, Facebook, and authentication pages commonly restrict embedding or behave differently in embedded browsers.
- A cross-origin iframe is isolated. The parent PWA cannot read its DOM or dispatch arbitrary trusted touch interactions into it. A JavaScript synthetic swipe in the parent page does NOT become a real user swipe inside an arbitrary third-party iframe.
- Therefore, the PWA can demonstrate gestures against its own first-party Motion Lab / demo feed and its own UI. It must NOT claim it can control Instagram Reels, YouTube Shorts, comments, or arbitrary cross-origin websites from an iframe.
- For restricted websites, show a clear explanation and a working “Open in browser” / external handoff. Never bypass X-Frame-Options or CSP, proxy arbitrary websites to strip their security headers, clone the site, scrape credentials, or fake a working login.
- The future native Android version can directly load the website in an Android WebView rather than an iframe. That is a different platform integration and must be implemented/tested separately. Even Android WebView has compatibility and OAuth restrictions; do not guarantee every site works.

4.3 Known source defects / risks to address

1. src/motion/observatory.ts references pulseStart in the animation loop and in pulse(), but the supplied file does not declare or initialize pulseStart. Declare and initialize it correctly (for example, -1) or remove the incomplete code. Add a regression check and run TypeScript.

2. The placement defaults are inconsistent. observatory.ts has fallback placements, but public/motion/config/scene-defaults.json is merged over them and overrides several values. Inspect the portalCore transform carefully. The generated portal_core.glb is a disc in its local XZ plane; the current config has a zero rotation, which may leave the core horizontal rather than aligned vertically with the portal/browser opening. Fix the geometry or transform so it sits in the intended vertical opening. Do not guess: visually verify it in the actual running Three.js scene.

3. resolveAddress() currently clears url.hash. Preserve URL fragments unless there is a tested reason not to; hash fragments are meaningful for SPA routing and anchor links. Add a regression test.

4. embed.functions.ts performs a server-side fetch to a user-supplied hostname and allows automatic redirects. It validates the first hostname but does not revalidate every redirect destination and its resolved addresses. This is an SSRF risk if exposed. Prefer removing the server-side probe if it is unnecessary. If retained, implement safe manual redirect handling with a strict redirect limit and revalidate protocol, hostname, DNS results, and private/reserved IP ranges at every hop. Fail closed. Never use it as an arbitrary page proxy.

5. isBlockedHost() is incomplete for all special-use / private address ranges and IPv6 representations. Harden it with a well-tested parser/library or a carefully tested implementation. Add tests for IPv4-mapped IPv6, IPv6 loopback, unique-local, link-local, multicast, unspecified, carrier-grade NAT, and reserved ranges. Avoid false confidence from a few regex checks.

6. Browser security policy should distinguish a known blocked site from a site whose support is unknown. A successful HTTP header probe does not guarantee that a site will work inside an iframe. Do not show “supported” unless actual browser behavior has been tested.

7. site-profiles.ts explicitly marks Instagram and YouTube as experimental with feed=false and comments=false, with a note that no gestures are sent into those sites. This is an honest current limitation. Keep that honesty. In the PWA prototype, these profiles must remain unsupported for in-frame gesture control unless genuine support is demonstrated without bypassing security boundaries.

8. animations/*.json are primarily tiny timing/property descriptors; they are not automatically playing animations. Lottie files are basic simple shapes. Integrate the existing files or replace/refine them with working animations; do not say animations are complete merely because JSON files exist.

9. audio files are short generated synthetic tones and one simple ambience loop. They are present but not known to be connected to UI events. Add optional controls and actual event integration. Default ambience off or very quiet; respect reduced-motion, mute, and system preferences.
